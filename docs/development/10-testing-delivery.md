## 最小端到端矩阵

| 场景 | 核对点 |
| --- | --- |
| 登录、刷新、退出、改密 | 401/403 区分，刷新轮换，旧 Token 失效 |
| 跨租户访问 | 知识库、文档、任务、Trace 与聊天都拒绝越权 |
| 用户会话访问 | 同租户另一用户不能越过所有权限制 |
| 上传文本 | S3、文档、任务、步骤、Chunk、向量一致 |
| 重复/并发上传 | 返回已有记录，无重复有效内容 |
| 解析失败、模型失败 | FAILED 及正确步骤，重试从预期阶段恢复 |
| RAG 命中/无证据 | 引用归属正确，无依据短路 |
| 多轮追问 | history/summary/last_route 契约一致 |
| SSE 正常/异常/取消 | final 持久化，error/done 不误判成功，无重复助手消息 |
| 检索调试 | 各阶段数量/耗时合理，过滤正确 |
| 测评 | 九组开关正确、失败计入统计、重启限制明确 |
| 前端刷新直达 | 路由回退、角色守卫、Token 刷新和 Long ID 精度 |

测试数据使用独立租户和可删除知识库，模型调用注明成本及预期输出。失败场景可通过不可用的测试端点、超时或替身模拟，不破坏共享生产服务。

## 新功能开发路径

新增 Java 接口：请求/响应 → 权限与所有权 → Service/事务 → Mapper/SQL → Controller → 前端类型和页面 → 正常/越权/失败验证。

新增 RAG 算法：确定 Engine 接口 → 内部 Schema → 参数默认 → 降级与 Trace → 调试可见 → 单变量消融 → 质量/延迟比较。不要同时修改切分、模型、召回、重排却只给一个总分。

新增入库步骤：确定阶段与细粒度编码 → 执行器注册 → 事务/幂等 → 步骤展示 → 重试恢复映射 → 失败测试。只新增枚举不会自动注册执行器。

修改数据库：新增前向 Flyway SQL → 检查旧数据回填 → 更新实体/Schema/索引 → 在备份副本验证 → 明确锁与回退条件。不要改已执行脚本去绕过校验。

修改配置：更新实际绑定位置、示例和配置参考；对重复命名（Java/Python Embedding、summary/redis 前缀）做生效验证。
