# Step 16：RAG 平台聊天前端

## 1. 目标

将原有接口测试页面升级为 RAG 平台前端。点击“RAG 对话”后进入独立聊天工作区：

```text
左侧：新建对话、搜索、会话列表
右侧：消息记录、引用信息、问题输入框
```

技术栈：

```text
React + TypeScript + Vite
```

## 2. 页面职责

前端负责：

- 展示会话列表。
- 新建、切换和删除会话。
- 加载会话消息。
- 发送问题。
- 展示模型回答和引用分片。
- 保存当前选择的知识库。
- 展示请求中和失败状态。

前端不负责：

- 伪造租户和用户身份。
- 直接查询 PostgreSQL。
- 执行向量检索。
- 保存正式会话历史。
- 直接持有模型 API Key。

## 3. 数据流

```text
用户选择会话
  -> GET Java 会话消息
  -> 渲染消息列表

用户发送问题
  -> POST Java Chat API
  -> Java 调用 Python
  -> Java保存消息
  -> 前端追加回答
```

## 4. 当前接口限制

在登录功能完成前，Java 可能无法从真实登录态获取用户信息。开发阶段可以通过固定请求头或测试用户上下文运行，但生产环境必须由认证中间件生成可信的 `tenantId` 和 `userId`。

会话列表为空不一定是前端渲染问题，也可能是请求没有携带 Java `RequestContextFilter` 需要的用户上下文。

## 5. 交互要求

- 左侧列表应固定宽度并支持滚动。
- 当前会话需要高亮。
- 新对话进入空白欢迎状态。
- 切换会话后加载对应消息。
- 请求过程中禁止重复提交。
- 长消息和长文件名不能撑破布局。
- 引用信息默认简洁展示，可按需展开。

## 6. 验收标准

- 点击“RAG 对话”进入聊天工作区。
- 可以创建新对话。
- 可以加载并切换已有会话。
- 可以删除会话。
- 可以通过 Java Chat API 发送问题。
- 回答和引用可以正确展示。
- 页面刷新后会话历史仍来自数据库。
