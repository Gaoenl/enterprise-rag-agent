# Step 18：问题独立化、意图路由与知识库选择

## 1. 目标

将固定知识库查询升级为具有基础问题理解和检索决策能力的流程：

```text
原始问题 + 会话历史
  -> 问题独立化
  -> 意图路由
  -> 知识库选择
  -> 检索查询改写
  -> RAG 检索或普通问答
```

## 2. 为什么先做问题独立化

追问通常依赖历史：

```text
历史：论文使用了 Transformer。
当前问题：它有哪些优势？
```

独立化后：

```text
论文使用的 Transformer 模型有哪些优势？
```

路由器和检索器使用独立问题，避免把“它”当作实际检索关键词。

问题独立化只补全指代，不回答问题、不扩展不存在的事实。

## 3. 意图类型

```text
GENERAL_CHAT  普通对话，不检索
RAG_QA        企业知识库问答，需要检索
FOLLOW_UP     对历史知识库回答的追问
CLARIFY       信息不足，需要用户澄清
UNSUPPORTED   当前系统不支持的操作
```

第一版使用规则路由。用户明确选择知识库时优先进入 RAG；问候进入普通对话；制度、文档、合同、项目资料等问题进入 RAG。

后续可以在规则低置信度时使用 LLM 结构化分类。

## 4. 知识库选择

选择优先级：

1. 用户明确选择的知识库。
2. 会话绑定的知识库。
3. 问题匹配到唯一知识库。
4. 当前租户只有一个可用知识库。
5. 多个候选无法判断时要求用户选择。

指定知识库必须校验租户归属、启用状态和软删除状态。无权限时不能自动切换到其他知识库。

## 5. 检索查询改写

问题独立化让问题可以被理解；检索查询改写让问题更适合召回：

```text
独立问题：
公司的差旅住宿费报销上限是多少？

语义检索查询：
公司差旅制度中住宿费报销标准和金额上限
```

查询改写失败时使用独立问题降级，不能阻断主流程。

## 6. Chat 响应调试字段

```json
{
  "question": "它有哪些优势？",
  "standaloneQuery": "Transformer 模型有哪些优势？",
  "intent": "FOLLOW_UP",
  "needRag": true,
  "knowledgeBaseId": 331377006161694720,
  "routeReason": "当前问题是对历史回答的追问",
  "mode": "rag"
}
```

这些字段便于开发阶段检查决策，生产环境可以不直接展示 `routeReason`。

## 7. 降级策略

- 独立化失败：使用原始问题。
- 查询改写失败：使用独立问题。
- 缺少租户：拒绝 RAG 检索。
- 指定知识库无效：返回澄清或业务错误。
- 多知识库无法选择：返回候选知识库。
- 路由无法判断：第一版按普通对话处理。

## 8. 验收标准

- 多轮追问能生成合理的独立问题。
- 普通问候不会触发检索。
- 企业文档问题会进入 RAG。
- 指定知识库会校验租户归属。
- 多个知识库无法判断时不会任意选择。
- 响应包含路由决策和实际知识库信息。
